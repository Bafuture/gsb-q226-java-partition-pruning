# 表分区裁剪与分区级索引

从零实现的 Java 表分区组件：按分区键把数据分到多个分区，每个分区维护自己的
有序索引；查询时先按分区键谓词**裁剪分区**，再只在候选分区内做点查/范围查询，
最后跨分区归并、去重、按指定键排序。无任何外部运行时依赖，仅用 JUnit 5 + AssertJ
做测试。

## 运行

```bash
mvn -q verify          # 编译 + 跑全部测试（15 个）
mvn -q compile exec:java -Dexec.mainClass=...  # 未配置 exec 插件，可用下面命令跑演示
java -cp target/classes com.example.gsb.partition.PruningDemo
```

## 包结构（`com.example.gsb.partition`）

| 类型 | 职责 |
|------|------|
| `Row` | 数据行：主键 `id`、分区键来源 `ts`（epoch day）、`payload` |
| `KeyRange` | 左闭右开长整型区间，提供 `overlaps` / `contains` |
| `PartitionScheme` | 分区策略接口：`partitionOf(key)`、`boundsOf(id)`、等值候选 |
| `DateRangePartitionScheme` | 按天 / 按自然月日期分区，分区 id 即日期字面量（如 `2024-03`） |
| `HashPartitionScheme` | 固定桶数的哈希分区（如 `bucket-7`），仅等值可裁剪 |
| `PartitionIndex` | 分区内主键有序索引（TreeMap）：点查、主键区间扫描、索引大小统计 |
| `Partition` | 一个分区 = id + 键范围 + 自己的索引，`drop()` 清空索引 |
| `PartitionQuery` | 查询条件：分区键等值/范围 + 可选主键区间 |
| `PruningReport` | 裁剪报告：裁剪前/后扫描分区数、被裁剪分区、裁剪比例 |
| `KWayMerger` | 跨分区 K 路归并，按主键有序、按主键去重（保留 `ts` 最大的最新行） |
| `PartitionedTable` | 门面：写入路由、裁剪规划 `plan`、点查 `get`、扫描 `scan`、增删分区、统计 |
| `PruningDemo` | 分区键选择对裁剪效果影响的可运行对比 |

## 一条查询的执行流程

1. **裁剪**：`plan(query)` 取全部分区，等值查询按策略精确命中一个分区；
   范围查询保留键范围与查询区间相交的分区。`PruningReport` 给出
   “裁剪前 12 个分区 → 裁剪后 2 个，裁剪率 83.3%”这类对比。
2. **分区内查询**：只对候选分区调用其索引做点查（`get`）或主键区间扫描
   （`TreeMap.subMap`，O(log n)）。
3. **行级过滤**：范围可能只落在分区内部（如按月分区只查其中 10 天），
   归并后对每一行再做一次分区键谓词校验，保证结果精确。
4. **合并去重排序**：K 路归并候选分区结果，按主键有序；同一主键出现在多个
   分区时保留 `ts` 最大的行；可传 `Comparator` 改按其他键排序。

## 分区新增与删除

- 写入时目标分区不存在会自动创建（`PartitionedTable.put`）。
- `dropPartition(id)` 会把分区从表中摘除并调用 `Partition.drop()` 清空其
  TreeMap 索引，此后任何 `plan/scan/get/stats` 都不再引用它；测试
  验证了统计消失、点查落空、扫描候选不含该分区，以及同 id 分区可干净重建
  （旧数据不会复活，即无悬挂引用）。

## 分区键选择对裁剪效果的影响（需求 7）

结论：**分区键必须与高频查询的过滤谓词对齐，且粒度要与查询范围匹配。**

同一份数据（2024 全年，每天 20 行，共 7320 行）、同一条查询
（2024-06-10 ~ 2024-06-20，共 200 行），`PartitionKeyChoiceComparisonTest`
实测对比：

| 分区键选择 | 裁剪前分区数 | 裁剪后分区数 | 候选分区内行数（经索引过滤前） |
|---|---:|---:|---:|
| 按月日期（谓词对齐，粒度粗） | 12 | 1 | 600 |
| 按天日期（谓词对齐，粒度细） | 366 | 10 | 200 |
| 按时间哈希 16 桶（谓词不对齐） | 16 | 16 | 7320 |

- **按时间范围查询 + 时间分区键**：谓词与分区边界对齐，范围裁剪直接生效。
- **按时间范围查询 + 哈希分区键**：哈希桶内键离散，桶范围是全域，范围谓词
  无法排除任何桶，裁剪率为 0%；哈希分区只对**等值**查询有效（点查精确命中
  1/16 桶，见测试中的等值对比）。
- **粒度权衡**：按月分区只扫 1 个分区但读到 600 行（放大 3 倍）；按天分区
  扫 10 个分区但只读 200 行（零放大），分区元数据开销却更大。粗粒度适合
  大范围分析查询，细粒度适合窄窗口点查/范围查询，需按真实查询模式选择。
- 三种方案最终返回的结果集完全相同：裁剪只改变代价，不改变正确性。

## 测试覆盖

`PartitionedTableTest`：分区写入与自动建区、范围/等值裁剪及前后对比、
分区内点查与主键范围查询、删除分区的索引清理与无悬挂引用、跨分区归并去重
与按指定键排序、键范围/条数/索引大小统计。
`PartitionSchemeTest`：日期/哈希策略的边界往返、均匀分桶、非法参数。
`PartitionKeyChoiceComparisonTest`：不同分区键选择下裁剪效果的量化对比，
并断言三种方案结果一致。
